# T019: testAll with COBRA_RUNMAT=1 under RunMat (SC-002)

Tree: full clone at 5625ee3ef, run by runmat_testall.sh (TIME_LIMIT=20m).

## Result: SC-002 is NOT met under RunMat v0.6.2

v0.6.2 stops before the first line of test/testAll.m runs (the banner is not printed), with
`RunMat:MirAggregateShapeInvalid` ("cell literal rows realize different widths") reported at testAll.m:53:16.
The location is misreported. Cause, found by bisecting the tree file by file:

- test/verifyCobraFunctionError.m line 35, `parser.addParamValue('inputs',{},@iscell)`: an empty cell literal
  `{}` (registered blocking defect D26).
- The file is never called by testAll. Under v0.6.2 a `{}` in ANY .m file in the folder of the script being
  run stops that script before its first statement. Reproduced with a 3-line script plus a 3-line helper
  holding `c = {};` in the same folder (the helper is not called): the script prints nothing and fails with
  the same error at a misreported location.
- testAll.m on its own in a folder (no other files) gets past its start-up under v0.6.2 and reaches the
  initCobraToolbox call, so the testAll changes themselves (T015-T017) compile and run.
- verifyCobraFunctionError.m is the only file directly in test/ that contains `{}`.

Making SC-002 hold under v0.6.2 needs `{}` -> `cell(0, 0)` in test/verifyCobraFunctionError.m, which is outside
the files this feature may change (plan.md). Recorded as a deviation for the Gate 3 decision.
