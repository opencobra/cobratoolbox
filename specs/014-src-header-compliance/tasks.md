# Tasks: src/ Function Header Documentation Compliance

**Input**: Design documents in `specs/014-src-header-compliance/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/header-rules.md, quickstart.md

**Tests**: The compliance checker IS the test (a `matlab.unittest` CI gate). Remediation is
documentation-only and behaviour-preserving; the executable-line diff check and the Sphinx
parse are the supporting verifications. No new numerical/solver test is required (FR-008).

**Organization**: US1 (checker + CI gate) is the blocking foundation. US2 (every input/output
documented) and US3 (used struct fields documented) are discharged **together per leaf folder**
— an agent remediating a folder applies the full rule catalog to every file in that folder, so
each per-folder task carries the `[US2]` label and also discharges US3 for its files.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: parallelizable (touches only its own folder's files; no dependency on another
  incomplete remediation task). All per-folder remediation tasks are `[P]` with respect to each
  other and depend only on the foundational phase (US1).
- Every task names exact paths. The rule catalog is `specs/014-src-header-compliance/contracts/header-rules.md`.

## Phase 3: US2 & US3 — per-leaf-folder header remediation (full fan-out)

**Goal**: every in-scope `src/*.m` header reaches zero error-severity violations — description +
`USAGE:`, every declared output and every consumed input/name-value parameter on a dedicated line,
and every struct field the function **uses** documented as `* .field - description` (interrogate
the body; use only fields the function reads/writes; take field meanings from `COBRAModelFields.rst`
/ `solveCobraLP.m` / `optimizeCbModel.m`; never fabricate). Behaviour-preserving: comments +
signature-whitespace only.

**Per-task procedure** (identical for every folder task below):
1. Read every in-scope `.m` file in the folder and its body (Principle V: map before editing).
2. Apply the full rule catalog in `contracts/header-rules.md`, interrogating the code for inputs,
   outputs, name-value params, and used struct fields.
3. Self-verify: `testHeaderCompliance('report', '<folder>')` → 0 error-severity violations.
4. Confirm comments-only: `test/verifiedTests/documentation/checkCommentsOnly.sh` clean for the folder's files.
5. Do NOT touch excluded-vendored files or any non-comment line.

**Independent test**: `testHeaderCompliance('report','<folder>')` reports 0 error-severity
violations and a spot check shows each input/output/used-field documented.
